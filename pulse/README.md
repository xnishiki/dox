# Pulse

Десктопный музыкальный плеер для Windows: популярная музыка, категории, персональный «Поток», 10-полосный эквалайзер, плейлисты с совместным редактированием и синхронизацией. Без подписок — только регистрация.

**Стек:** Electron · React · TypeScript · Vite · Zustand · Tailwind CSS · Framer Motion · lucide-react · Web Audio API · Supabase.
**Музыка:** [Jamendo](https://www.jamendo.com) — бесплатные легальные полные треки под лицензиями Creative Commons, плюс твои локальные файлы.

## Возможности

- **Главная:** «Топ сейчас» (неделя / месяц / всё время), «Новинки», «Популярные альбомы», «Популярные исполнители», большая кнопка «Потока» с визуализацией.
- **Категории:** 24 цветные карточки жанров и настроений (для тренировки, для сна, для работы…). Страница категории: популярные треки, альбомы, исполнители, «Слушать всё».
- **Поиск** по трекам, альбомам, исполнителям и публичным плейлистам, с подсказками и историей запросов.
- **Плеер:** play/pause, назад/вперёд, перемотка, перемешивание, повтор (выкл / всё / один), громкость, «нравится», очередь с перетаскиванием, полноэкранный режим «Сейчас играет» с фоном из цветов обложки.
- **«Поток»:** бесконечная персональная волна по лайкам, дослушиваниям, пропускам и любимым жанрам; «нравится» / «не нравится»; настроение, характер, жанры.
- **Эквалайзер:** 10 полос (32 Гц – 16 кГц) на `BiquadFilterNode`, ±12 дБ, 9 предустановок, свои пресеты, предусилитель, вкл/выкл, график АЧХ.
- **Плейлисты:** создание, переименование, обложка (картинка или коллаж из 4 обложек), описание, добавление через контекстное меню, drag-and-drop, удаление; приватный / по ссылке / публичный; совместные плейлисты; код `PULSE-7F3K` и ссылка `pulse://join/PULSE-7F3K`; подписки; раздел «Публичные»; экспорт и импорт `.json`; работа без интернета с синхронизацией при подключении.
- **Локальные файлы:** mp3, flac, wav, ogg (а также m4a, opus) из выбранной папки, с тегами и обложками.
- **Прочее:** окно без рамки со своими кнопками, иконка в трее, управление из плитки Windows и медиаклавишами, горячие клавиши, сохранение позиции/громкости/очереди, тёмная и светлая тема, русский и английский, адаптивность от 900 px.

### Горячие клавиши
| Клавиша | Действие |
|---|---|
| Пробел | пауза / играть |
| ← / → | перемотка на 5 секунд |
| ↑ / ↓ | громкость |
| Ctrl + F | поиск |
| Esc | закрыть меню, эквалайзер, «Сейчас играет» |
| Медиаклавиши | играть, пауза, следующий, предыдущий |

## 1. Ключ Jamendo

1. Зарегистрируйся на **https://devportal.jamendo.com** (бесплатно).
2. *My Applications → Add an application*: любое название, сайт можно указать `http://localhost`.
3. Скопируй **Client ID** (8 символов).
4. Укажи его одним из способов:
   - в файле `.env` (скопируй `.env.example` → `.env`): `VITE_JAMENDO_CLIENT_ID=твой_ключ` — ключ встроится при сборке;
   - или прямо в приложении: **Настройки → Ключи сервисов**.

> Файл `.env` не попадает в git (он в `.gitignore`). Учти: ключ клиентского приложения нельзя спрятать от пользователя полностью — `.env` лишь не даёт ему попасть в репозиторий. Для Jamendo это нормально: Client ID — публичный идентификатор приложения.

## 2. Supabase: аккаунты и общие плейлисты

Без Supabase приложение полностью работает локально (лайки, плейлисты, «Поток» хранятся на компьютере). Аккаунты нужны для синхронизации между устройствами, совместных плейлистов, кодов-приглашений и публичных плейлистов.

1. Создай проект на **https://supabase.com** (бесплатный тариф подходит).
2. **SQL Editor → New query** → вставь целиком файл [`supabase/schema.sql`](supabase/schema.sql) → **Run**.
   Скрипт создаёт таблицы, политики Row Level Security, триггеры и функции; его можно запускать повторно.
3. **Authentication → Sign In / Providers → Email**: включён по умолчанию.
   - Чтобы входить сразу после регистрации, отключи **Confirm email**.
   - Если оставить подтверждение — пользователь получит письмо и войдёт после перехода по ссылке.
4. **Project Settings → API**: скопируй **Project URL** и ключ **anon public**.
5. Впиши их в `.env`:
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```
   или в приложении: **Настройки → Ключи сервисов**.

### Что в базе
| Таблица | Назначение |
|---|---|
| `profiles` | имя пользователя (создаётся автоматически при регистрации) |
| `playlists` | плейлисты: название, описание, обложка, видимость, совместный ли, код `PULSE-XXXX`, треки (`jsonb`) |
| `playlist_members` | соавторы совместных плейлистов |
| `playlist_follows` | подписки на чужие плейлисты |
| `user_state` | лайки и история «Потока» для синхронизации |

### Правила доступа (RLS)
- Плейлист видят владелец, соавторы и — если он «по ссылке» или публичный — все вошедшие пользователи. В поиске показываются только публичные.
- Менять плейлист могут владелец и соавторы (если плейлист совместный). **Соавтор может менять только треки** — название, обложку, видимость и код меняет только владелец (это проверяет триггер).
- Удаляет плейлист только владелец; приглашает соавторов только владелец.
- `join_by_code('PULSE-XXXX')`: совместный плейлист — становишься соавтором; «по ссылке» или публичный — подписываешься; приватный — отказ.
- `user_state`, подписки — только свои.

> Ключ **anon** безопасно встраивать в приложение: доступ ограничивают политики RLS. Ключ **service_role** никогда не вставляй ни в приложение, ни в `.env`.

## 3. Запуск в режиме разработки

Нужен **Node.js 22** и Windows (для Electron-окна). Интерфейс можно разрабатывать и в браузере на любой ОС.

```bash
npm install
```
```bash
npm run dev
```
Откроется окно Pulse с горячей перезагрузкой.

Только интерфейс в браузере (без Electron: без трея, локальных файлов и кнопок окна):
```bash
npm run dev:web
```
Откройте http://localhost:5173

Проверка типов:
```bash
npm run typecheck
```

## 4. Сборка .exe

### На своём компьютере (Windows)
```bash
npm run dist
```
В папке `release/` появятся:
- `Pulse-Setup-<версия>.exe` — установщик (можно выбрать папку, создаёт ярлыки);
- `Pulse-Portable-<версия>.exe` — запускается без установки.

### Через GitHub Actions
Workflow [`.github/workflows/pulse-release.yml`](../.github/workflows/pulse-release.yml) собирает `.exe` на `windows-latest`:
- **пуш в ветку `pulse`** — сборка; готовые файлы появляются в ветке `pulse-dist` и во вкладке Actions (артефакт `Pulse-windows`);
- **пуш тега `v*`** — сборка и публикация **GitHub Release** с файлами автообновления (см. [раздел 5](#5-обновления); теги создаёт `npm run release`);
- вручную: Actions → «Pulse — сборка и релиз» → Run workflow (тестовая сборка).

Ключи для сборки (по желанию) — в **Settings → Secrets and variables → Actions**: `JAMENDO_CLIENT_ID`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`. Без них приложение соберётся, а ключи можно вписать в настройках.

В ветке `pulse-dist` файлы разбиты на части по 40 МБ (лимит GitHub — 100 МБ на файл). Склеить в Windows (PowerShell или cmd):
```bat
copy /b Pulse-Setup-0.1.0.exe.part00 + Pulse-Setup-0.1.0.exe.part01 + Pulse-Setup-0.1.0.exe.part02 Pulse-Setup-0.1.0.exe
```
Проверить контрольную сумму — со значением из `SHA256SUMS`:
```bat
certutil -hashfile Pulse-Setup-0.1.0.exe SHA256
```

> **SmartScreen.** Сборка не подписана сертификатом разработчика, поэтому при первом запуске Windows может показать «Система Windows защитила ваш компьютер» → **Подробнее → Выполнить в любом случае**. Подробнее — в разделе [«Подпись кода»](#подпись-кода-и-smartscreen).

## 5. Обновления

Установленный Pulse обновляется сам через **GitHub Releases** ([electron-updater](https://www.electron.build/auto-update)):

- при запуске (через ~8 секунд) и потом каждые 4 часа тихо проверяет, есть ли новая версия;
- если есть — скачивает её в фоне, **только изменившуюся часть** (по файлу `.blockmap`), музыка не прерывается;
- когда скачано — показывает уведомление «Доступна версия X.Y.Z» со списком изменений и кнопками **«Перезапустить и обновить»** и **«Позже»**;
- «Перезапустить и обновить» сохраняет трек, позицию, очередь и громкость — после обновления музыка продолжает играть с той же секунды;
- «Позже» — обновление ставится при следующем закрытии Pulse (крестик в этом случае закрывает приложение, а не прячет в трей);
- после обновления один раз открывается страница **«Что нового»** (из `CHANGELOG.md`);
- нет интернета или GitHub недоступен — проверка тихо пропускается; прерванная загрузка продолжится при следующей проверке или когда вернётся сеть;
- **portable-версия** не обновляется сама: она только сообщает о новой версии и даёт ссылку на страницу релиза.

В **Настройках → Обновления**: текущая версия, «Проверить сейчас», «Обновлять автоматически», канал **Стабильный / Бета**, дата последней проверки, прогресс загрузки (процент и скорость), ссылки на «Что нового» и на логи. Во время загрузки в боковой панели рядом с «Настройками» крутится маленькое кольцо прогресса, а когда обновление готово — появляется зелёный значок.

Логи обновлений пишутся через electron-log в `%APPDATA%\Pulse\logs\main.log` (кнопка «Открыть логи» в настройках).

> ⚠️ **Репозиторий с релизами должен быть публичным.** Приложение скачивает обновления без токена (и токен в приложение класть нельзя). Если репозиторий приватный, проверка тихо не находит обновлений. Варианты: сделать репозиторий публичным или публиковать релизы в отдельный публичный репозиторий — для этого поменяйте `owner`/`repo` в `package.json → build.publish` и в `dev-app-update.yml`, а в workflow добавьте `repository: owner/repo` и токен с правом записи в тот репозиторий (встроенный `GITHUB_TOKEN` пишет только в свой).

### Как выпустить обновление
1. Опиши изменения в `CHANGELOG.md`, в разделе `## [Unreleased]`, пунктами `- …` (можно с подзаголовками `### Добавлено`, `### Исправлено`).
2. Закоммить всё и выполни одну команду:
   ```bash
   npm run release -- patch
   ```
   `patch` — исправления (0.2.0 → 0.2.1), `minor` — новые возможности (0.2.0 → 0.3.0), `major` — большие изменения (0.2.0 → 1.0.0). Проверить, что получится, ничего не меняя: `npm run release -- minor --dry-run`.
3. Скрипт поднимет версию в `package.json`, перенесёт пункты в раздел новой версии в `CHANGELOG.md`, сделает коммит, тег `vX.Y.Z` и запушит их.
4. GitHub Actions соберёт приложение (~5–10 минут) и опубликует релиз с файлами `Pulse-Setup-X.Y.Z.exe`, `Pulse-Setup-X.Y.Z.exe.blockmap`, `latest.yml`, `beta.yml` и portable-версией. Текст релиза — раздел версии из `CHANGELOG.md`.
5. Установленные Pulse найдут обновление при следующей проверке (максимум через 4 часа или при перезапуске).

Если тег не удалось запушить (ограничения окружения, нет прав), ветка с коммитом версии всё равно уходит на GitHub. Тег тогда создаётся на странице GitHub: **Releases → Draft a new release → Choose a tag → впиши `vX.Y.Z` → Create new tag, Target — ветка `pulse` → Publish release**. Workflow подхватит тег, соберёт приложение и сам добавит в этот релиз файлы и текст из `CHANGELOG.md`.

Защита от ошибок: скрипт не даст выпустить версию с существующим тегом и с пустым списком изменений, а workflow проверяет, что тег совпадает с версией в `package.json` и что у такого релиза ещё нет файлов.

**Бета-канал.** `npm run release -- minor --beta` выпустит `0.3.0-beta.1` (на GitHub — pre-release), `npm run release -- beta` — следующую бету `0.3.0-beta.2`, а `npm run release -- minor` из беты — финальную `0.3.0`. Бету получают только те, у кого в настройках выбран канал «Бета»; стабильные версии они тоже получают.

> Первая версия с автообновлением (0.2.0) ставится вручную — у 0.1.0 механизма обновлений ещё нет. Дальше всё приходит само.

### Проверить автообновление локально
В режиме разработки обновления выключены. Чтобы проверить их без установки:
1. В `dev-app-update.yml` уже указан источник обновлений (тот же репозиторий).
2. Временно поставь в `package.json` версию ниже опубликованной (например `0.0.1`) — **не коммить это**.
3. Запусти с переменной окружения (PowerShell):
   ```powershell
   $env:PULSE_DEV_UPDATE=1; npm run dev
   ```
   Pulse проверит GitHub Releases как установленная версия: увидит новую, скачает её и покажет уведомление. Весь процесс виден в логе `%APPDATA%\Pulse\logs\main.log`. Установку из dev-режима делать не нужно — проверьте уведомление и прогресс, затем верните версию.

Для проверки «вживую»: установите старую версию из релизов и выпустите новую — установленная найдёт её в течение 8 секунд после запуска (или кнопкой «Проверить сейчас»).

### Как откатить неудачный релиз
Автообновление не ставит версию ниже установленной, поэтому «откат» — это выпуск новой, исправленной версии:
1. **Сразу остановить раздачу:** на GitHub открой релиз → **Edit** → поставь галочку **Set as a pre-release** (или удали файл `latest.yml` из релиза, или удали релиз целиком). Стабильный канал вернётся к предыдущему релизу, и новые установки перестанут скачивать плохую версию. Если релиз удалить, удалите и тег: `git push origin :refs/tags/vX.Y.Z`.
2. **Исправить для тех, кто уже обновился:** откатите проблемный коммит (`git revert <коммит>`), добавьте пункт в `## [Unreleased]` и выпустите `npm run release -- patch`. Все получат исправленную версию.
3. Если нужно вернуть именно старый код — `git revert` проблемных коммитов и снова `npm run release -- patch`: номер версии всегда растёт, даже если код как в старой.

### Подпись кода и SmartScreen
Сборка не подписана сертификатом разработчика (code signing). Поэтому:
- при **первой установке** Windows SmartScreen показывает «Система Windows защитила ваш компьютер» / «Неизвестный издатель» → **Подробнее → Выполнить в любом случае**;
- **обновления при этом работают**: electron-updater проверяет целостность файла по SHA-512 из `latest.yml`, а установщик обновления запускается без окна SmartScreen;
- чтобы убрать предупреждение совсем, нужен сертификат подписи кода (OV или EV) — его подключают в electron-builder через секреты `CSC_LINK` и `CSC_KEY_PASSWORD` в GitHub Actions. Тогда electron-updater дополнительно проверяет, что обновление подписано тем же издателем.

## Как устроен «Поток»

1. Каждое событие пишется в историю: **дослушал** (≥ 85 % трека) +1, **нравится** +3, **пропуск** (< половины и < 30 с) −0,6, **не нравится** −3. Вес события затухает с полупериодом 2 недели.
2. Из истории считаются веса жанров/тегов и исполнителей; выбранные в настройках жанры получают бонус.
3. Для каждой порции берутся 2 жанра случайно пропорционально весам и 1 «новый» жанр — около 25 % треков для разнообразия.
4. Настроение превращается в теги Jamendo (бодрое → energetic/happy, спокойное → calm/relaxing, грустное → sad/melancholic); характер — в сортировку (любимое → популярное за месяц + треки любимых исполнителей, новое → по дате выхода, популярное → за неделю).
5. Кандидаты оцениваются, недавно игравшие и дизлайкнутые исключаются, один исполнитель не идёт дважды подряд. Когда в очереди остаётся ≤ 3 трека, подгружается следующая порция.
6. История хранится на компьютере и синхронизируется с аккаунтом (`user_state`).

## Ограничения

- **Spotify, Яндекс Музыка, SoundCloud** не подключены: они не разрешают сторонним приложениям бесплатно проигрывать полные треки. Pulse использует Jamendo — там другой каталог (независимые артисты), зато всё легально и бесплатно.
- Локальные файлы в общем плейлисте играют только на том компьютере, где они лежат.
- Совместное редактирование: при одновременном изменении порядка треков двумя людьми сохраняется более позднее изменение.
